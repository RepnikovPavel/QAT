# Reproduction guide — 2× RTX 4090 (Ada sm_89) server

How to run the Q² reproduction on the **4090 box** (Ada sm_89, CUDA 12.7 max via
driver 565), which needs a different image than the Blackwell (cu128) guide in
`q2_voc.md`. This recipe uses the `Dockerfile.cu126` build (cu126 = shared
denominator that also loads on a CUDA-13 host) and writes everything to the
server's writable disk.

This supersedes the dataset/run path assumptions of `q2_voc.md` (which assume
the Blackwell server with `/mnt/hdd2`). Nothing else changes — same code, same
hyperparameters (Appendix 8.1), same targets (Table 1).

## 0. Paths on the 4090 server

| What | Path | Notes |
| --- | --- | --- |
| repo clone | `/mnt/data1/logchecker/qat_repo` | on the writable 1.8 TB disk |
| datasets | `/mnt/data1/logchecker/qat_repro/datasets/{voc,coco,busi}` | |
| YOLO weights | `/mnt/data1/logchecker/qat_repro/weights/yolov5s.pt` | COCO-pretrained body |
| run outputs | `/mnt/data1/logchecker/qat_repro/qat_run/<run>` | checkpoints + logs |
| Docker image | `qat-repro-cu126` | built from `docker/Dockerfile.cu126` |

Do NOT use `/mnt/data2` (the Docker data-root) for datasets/runs — it is 100 %
full. `/mnt/data1/logchecker/` is owned by us and has ~900 GB free.

## 1. Clone + build the image

```sh
cd /mnt/data1/logchecker
git clone -b glm52/fix-q2-obj-collapse https://github.com/RepnikovPavel/QAT.git qat_repo
cd qat_repo
docker build -t qat-repro-cu126 -f docker/Dockerfile.cu126 .
```

Verify the GPU + Ada capability:

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python -c \
  "import torch; print(torch.__version__, torch.cuda.is_available(), \
                        torch.cuda.get_device_capability(0))"
# expect: <torch>+cu126 True (8, 9)
```

`docker_run.sh` picks the `cu126` image + Dockerfile via `PLATFORM=cu126` and
mounts `DATA_DIR` (so `--voc` / `--out` paths inside the container resolve to the
right host disk). Set both as env vars for every command below.

## 2. Prepare datasets (idempotent)

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh bash scripts/download_datasets.sh \
  /mnt/data1/logchecker/qat_repro/datasets voc
```

## 3. Get yolov5s.pt (COCO-pretrained body)

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python -c "import torch; \
    torch.hub.download_url_to_file('https://github.com/ultralytics/yolov5/releases/download/v7.0/yolov5s.pt', \
    '/mnt/data1/logchecker/qat_repro/weights/yolov5s.pt')"
```

## 4. Unit tests (CPU, fast)

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python -m pytest methods/q2/tests/ -q -m "not gpu"
```

## 5. M0 — gradient-imbalance probe (Fig. 1b, fast)

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python -m qat.probe_imbalance \
  --quant lsq --wbits 4 --abits 4 --steps 120 \
  --voc /mnt/data1/logchecker/qat_repro/datasets/voc \
  --data /mnt/data1/logchecker/qat_repro/qat_run/voc_yolo \
  --pretrained /mnt/data1/logchecker/qat_repro/weights/yolov5s.pt \
  --out /mnt/data1/logchecker/qat_repro/qat_run/m0
```

Expected (sanity, matches the Blackwell reproduction in `RESULTS.md`): under W4A4
the deep-branch gradient energy dominates (ratio ≫ 1); with `use_qgb` the two
energies converge (ratio → 1).

## 6. Train — baseline LSQ W4A4 (issue #4 fix under test)

The objectness-collapse fix is: correct LSQ step gradient (Esser `q − x/s`),
quant params in a weight_decay=0 group, `project_quant_steps`, init on a real
batch, fake-quant ON from step 0 (paper schedule, no FP warmup), `clip_grad`.

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python -u -m qat.train_detect \
  --quant lsq --wbits 4 --abits 4 \
  --epochs 30 --batch 16 \
  --voc /mnt/data1/logchecker/qat_repro/datasets/voc \
  --data /mnt/data1/logchecker/qat_repro/qat_run/voc_yolo \
  --pretrained /mnt/data1/logchecker/qat_repro/weights/yolov5s.pt \
  --out /mnt/data1/logchecker/qat_repro/qat_run/m1_lsq_baseline_4090
```

Watch the per-iteration `omax0=` (raw obj-sigmoid max). A healthy run stays well
above 0.1; the pre-fix collapse dropped it to ~0.001 within a few steps.

## 7. Evaluate mAP@0.5

```sh
PLATFORM=cu126 DATA_DIR=/mnt/data1/logchecker/qat_repro \
  scripts/docker_run.sh python scripts/eval_any.py \
  --ckpt /mnt/data1/logchecker/qat_repro/qat_run/m1_lsq_baseline_4090/ckpt_ep29.pt \
  --test-list /mnt/data1/logchecker/qat_repro/qat_run/voc_yolo/test.list
```

Target: mAP@0.5 ≈ **76.9** (Table 1, LSQ W4A4 baseline).
