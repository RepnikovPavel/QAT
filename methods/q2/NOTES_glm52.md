# Заметка: glm52 не воспроизвёл рецепт Q²

Дата: 2026-07-31
Агент: **glm52** (ZCode, модель builtin:zai-coding-plan/GLM-5.2)
Ветка: `glm52/fix-q2-obj-collapse`

## Постановка

Задача: точно воспроизвести результаты статьи Q² (arXiv:2511.05898) на сервере
2× RTX 4090 (Ada sm_89, cu126), построчно сверяясь со статьёй через сервис
парсинга ocrc. Цель — совпадение абсолютных чисел (FP 85.9, LSQ W4A4 76.9, Q²
78.9, дельта +2.0).

## Итог: НЕ воспроизведено

Точный рецепт из статьи **не воспроизведён**. Ни абсолютные числа, ни дельта Q²
(+2.0) не достигнуты. Это честная фиксация неудачи, а не отчёт об успехе.

### Полученные числа (честный eval, полный VOC test, 4131 img)

| Run | ours | paper |
| --- | --- | --- |
| FP YOLOv5s (офиц. yolov5 train, наш eval) | 0.792 | 0.859 |
| Baseline (LSQ W4A4, 30 ep, bs32×accum2, тёплый FP init) | 0.652 | 0.769 |
| Q² (Q-GBFusion + Q-ADA, старая Δ=teacher−student) | 0.651 | 0.789 (+2.0) |
| Q² (Q-GBFusion + Q-ADA, Eq13 Δ=\|X−Q(X)\|) | 0.650 | 0.789 (+2.0) |

**Дельта Q² vs baseline ≈ 0** (0.650/0.651 vs 0.652), статья обещает **+2.0**.

## Что было сделано (по ходу), но не привело к совпадению

1. Распарсил статью через ocrc, составил `SPEC_AUDIT.md` (построчное
   статья↔код).
2. Починил баг issue #4 (objectness collapse): корень — неверный LSQ step-градиент
   (переписан через autograd.Function, сверен с LSQ-статьёй). Это устранило
   mAP=0, но не дало абсолютных чисел.
3. Реализовал 4 «фикса верности статье»: `--init-ckpt` (тёплый FP-VOC старт из
   официального yolov5-чекпойнта 0.827), `--grad-accum` (эффективный batch 64),
   Q-ADA frozen teacher + SPPF hooks, Q-ADA Eq16 (Sigmoid(S)+L1).
4. Починил отдельный серьёзный баг: `eval_detect` занижал mAP на ~0.32 (1-IoU-
   колонка + matching в порядке детекций вместо yolov5/val.py `process_batch`).
   После переписывания FP читается 0.792 (офиц. val 0.827).
5. По A/B-эксперименту проверил обе версии Q-ADA — дельта ~0 в обоих случаях.

## Почему не сошлось (диагноз, не оправдание)

- **Дельта +2.0 не получена.** Перечитывание line 293 + Table 4 показывает, что
  Q-ADA даёт в основном *ускорение сходимости* (+0.3-0.7% accuracy), а Table 4
  измеряет **time-to-convergence с validation early-stopping, а не фиксированные
  эпохи**. Я же сравнивал на фиксированных 30 эпохах — на равном бюджете Q²
  закономерно даёт ~0. Для честного сравнения дельты нужен ран с протоколом
  статьи (early-stop по val).
- **Абсолютные числа ниже.** Эффективный batch: grad-accum=2 даёт 64, но
  BatchNorm видит 32 (статья — истинный batch 64 на 8 GPU). Плюс только 30 эпох
  (статья не фиксирует число эпох для детекции).

## Передача следующему агенту

Для достижения совпадения со статьёй нужны:
1. Протокол статьи — validation-based early-stopping, а не фикс-эпохи; сравнивать
   mAP на точке сходимости baseline vs Q².
2. Истинный batch 64 (DDP на 2 GPU, не grad-accum) — чтобы BN-статистики совпадали.
3. FP-учитель (0.827 от офиц. yolov5) уже есть как `--init-ckpt`.
4. Сверить Q-ADA на нескольких точках супервизии (fusion nodes 12/16/19/22), а
   не только на SPPF — статья говорит о множественных точках.

Q-GBFusion работает (M0: ratio 2.16→1.08; lambda/alpha обновляются в
тренировке), но на фикс-бюджете не конвертируется в +2 mAP.
